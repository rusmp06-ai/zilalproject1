# Читалка библиотеки — v0.9

## Чтение

PDF и TXT открываются в читалке общей библиотеки. PDF отображается постранично через PDF.js 6.4.299; встроенный worker собирается вместе с приложением, CDN не используется. Для PDF с текстовым слоем есть раскрываемый текст текущей страницы. Сканированные страницы читаются как изображения, OCR не выполняется.

TXT делится на стабильные страницы по 4000 Unicode-символов, без потери текста и разрыва суррогатных пар. Изображения остаются в просмотре. DOCX, PPTX, XLSX скачиваются для открытия в другом приложении; EPUB и конвертация офисных файлов пока не добавлены.

Есть предыдущая/следующая страница, переход по номеру, восстановление последней позиции и прогресс. Процент означает позицию текущей страницы относительно общего числа страниц, а не измерение времени чтения или знания материала. Возврат к ранней странице уменьшает процент.

## Личные отметки

Каждый участник может добавить материал в избранное из каталога или читалки. Фильтр «Только избранное» работает вместе с поиском и пагинацией. Закладки привязаны к номерам страниц: добавление/удаление и переход к странице. До 100 закладок на документ и 1000 документов с личными отметками на аккаунт.

При открытии и переходах сохраняются позиция и число страниц; избранное и закладки сохраняются после соответствующего действия. Сохранённые отметки восстанавливаются при повторном открытии. Ошибка сохранения видна в читалке. При конфликте версий кнопка «Обновить отметки» загружает актуальную запись: несохранённые изменения заменяются серверными, автоматического объединения нет.

## Доступ и синхронизация

Миграция `202610100008_reader.sql` добавляет `reader_states`, RLS и RPC `reader_state`, `save_reader_state`, `reader_library_catalog`. Пользователь определяется через `auth.uid()`, идентификатор другого аккаунта не принимается. Владелец платформы не читает отметки других участников. Привилегированный администратор базы технически имеет доступ; сквозного шифрования нет.

Чтение и сохранение требуют активного аккаунта, доступа к библиотеке и опубликованного материала с готовым файлом. Блокировка скрывает отметки, но не стирает их; восстановление возвращает позицию. При удалении публикации её отметки удаляются каскадно. Прямые клиентские записи запрещены. Версия проверяется атомарно, устаревшая вкладка не перезаписывает запись. Избранное фильтруется до ограничения в 50 строк.

Демо сохраняет личные отметки в localStorage существующей версии v08; старые данные получают пустое состояние чтения без сброса. Демо не является границей безопасности. В подключённом Supabase отметки будут храниться в базе и доступны с разных устройств, но настоящий Supabase здесь ещё не подключён и такая синхронизация не проверена.

## Проверки и ограничения

PGlite проверяет восстановление позиции, избранное за пределами первой страницы каталога, RLS для владельца, запрет прямых записей, конфликт версий, валидацию страниц и закладок, блокировку, восстановление и каскадное удаление. jsdom проверяет TXT-читалку, переход по номеру, закладки, избранное, повторное открытие и изоляцию аккаунтов.

В Chromium проверен двухстраничный PDF: отрисовка canvas и текстовый слой, навигация, прогресс, закладка, избранное, восстановление после перезагрузки, мобильный экран 390px. Этот же сценарий прошёл для единого `preview.html`, загруженного через локальный HTTP с сетью, отключённой после загрузки. Прямое открытие через `file://` заблокировано политикой браузера среды и здесь не проверено.

Сложные PDF с нестандартными шрифтами, CMap, защищённые паролем и интерактивные формы отдельно не проверены; формы и ввод PDF-пароля не реализованы. Проверка Supabase Auth/Storage и настоящих устройств остаётся отдельным этапом.

Для автономной демонстрации динамические импорты объединены в один JS-файл, PDF-worker встроен. Бандл увеличился примерно до 2.14 МБ (648 КБ gzip); Vite сообщает предупреждение о размере. Это сохраняет сборку в один HTML, но не является оптимизацией загрузки для публичного сайта.

### Повторить проверки

`npm test` проверяет модель, SQL и интерфейс, `npm run build:preview` собирает TypeScript и автономную демонстрацию. Для PDF-проверки запустите Vite (`npm run dev -- --port 5173 --strictPort`), затем `npm run test:reader:browser`. Требуется Chromium: путь по умолчанию `/usr/bin/chromium`, другой путь задаётся `CHROMIUM_PATH`. Тест использует отдельный браузерный контекст с локальной демонстрацией и сам создаёт временный двухстраничный PDF.

Для проверки автономной сборки обслуживайте каталог проекта локальным HTTP-сервером и задайте `READER_TEST_URL=http://127.0.0.1:5174/preview.html READER_TEST_OFFLINE=1 npm run test:reader:browser`. Сеть отключается после загрузки страницы и снова включается только для её перезагрузки. Этот тест не подключается к Supabase.

# Развёртывание

## Frontend

Node 22.22.2+ в ветке 22 или 24.15+ в ветке 24. Сборка: `npm ci`, затем `npm run build`; публикуемый каталог — `dist/`. Переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` публичные и задаются в настройках сборки Cloudflare Pages/Netlify. Никогда не использовать service_role на клиенте.

`preview.html` создаётся отдельно командой `npm run build:preview` при пустых `VITE_SUPABASE_*`. Он не входит в Git и не заменяет production-сборку. Для локальных браузерных проверок требуется Chromium; в CI он устанавливается Playwright.

## Supabase Auth

Email confirmation включено. Указать реальный HTTPS-адрес frontend в Auth → URL Configuration → Site URL и точные Redirect URLs для подтверждения и сброса пароля. Проверить регистрацию нового тестового студента и получение письма отдельно от входа существующего тестового аккаунта. Не отключать подтверждение ради прохождения теста.

## Edge Function material-analyze

Настройки хранятся в Supabase secrets, не в frontend:

- `GEMINI_API_KEY`, при необходимости `GEMINI_MODEL`;
- штатные серверные `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`;
- **`ALLOWED_ORIGINS`**: точные адреса frontend без завершающего `/`, через запятую. Пример: `https://studyhub.example,http://localhost:5173`.

Перед публикацией обновлённой функции задайте ALLOWED_ORIGINS. Запрос браузера с незарегистрированного Origin получает 403; wildcard и origin `null` не разрешены. Ответы содержат Vary: Origin. Запрос без Origin всё равно требует действительный bearer и право публикации: CORS не заменяет авторизацию.

Функция публикуется штатным способом `supabase functions deploy material-analyze` после проверки тестового проекта. Из этой среды функция и серверные secrets автоматически не публикуются. Обновление frontend само по себе не меняет CORS уже развёрнутой edge-функции.

## Проверка перед пилотом

Проверить сайт на медленной сети и физическом телефоне; регистрацию/письмо; вход отдельного студента; доступ к своей группе и отказ к чужим материалам; загрузку и чтение временного файла; расписание и разовую отмену; сдачу и проверку работы; восстановление пароля и черновиков. Записать фактические результаты в pilot-readiness.md. Демо и зелёный CI не считаются этой проверкой.

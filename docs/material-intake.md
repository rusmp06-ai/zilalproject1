# Добавление документов с Gemini — v0.31

> Справка отдельного этапа. Версии и результаты проверок ниже относятся к моменту его разработки. Текущие настройки — в [README](../README.md) и [развёртывании](deployment-current.md), подтверждённые результаты — в [готовности пилота](pilot-readiness.md).

Помощник находится в «Админ → Дисциплины и преподаватели», в публикациях библиотеки, в материалах дисциплины и на странице «Мои дисциплины» преподавателя. Выберите «Добавить документ с ИИ».

## Сценарий

1. Выберите файл до 10 МБ. Можно посмотреть оригинал до публикации.
2. Разрешите отправить документ в Gemini и нажмите «Распознать документ».
3. Проверьте название, тип и дисциплину. Помощник показывает причину, короткие цитаты и предполагаемую тему. Если дисциплина неизвестна или неоднозначна между группами, её нужно выбрать самостоятельно.
4. Исправьте поля при необходимости и нажмите «Утвердить и опубликовать». Дополнительное подтверждение показывает место публикации.

Лекции, презентации и материалы попадают в выбранную дисциплину. Книги — в общую библиотеку с авторством загрузившего пользователя и группой автора. Преподаватель может публиковать собственные книги, если у него есть действующее назначение в этой группе и доступ к библиотеке; это не даёт ему управление чужими книгами.

Задание создаётся только с правами преподавателя своей дисциплины или владельца. ИИ не назначает срок и максимальный балл: эти поля проверяет человек. Исходный файл прикладывается к заданию и доступен студенту по кнопке «Открыть исходный документ задания». Краткое описание ИИ не заменяет полный оригинал. Прикреплённый файл защищён от удаления как обычный материал. Староста без полномочий преподавателя может распознать такой файл, но не назначить задание.

Сначала создаётся резерв файла, затем выполняются загрузка и подтверждение. Финализация публикации и создание задания выполняются в одной транзакции. Повтор в той же открытой форме использует прежний идентификатор и не создаёт дубликат. Если загрузка не завершена, её можно повторить с теми же полями и файлом; либо удалить незавершённый материал в соответствующем разделе. После перезагрузки формы резерв автоматически не восстанавливается: проверьте незавершённые материалы перед новой отправкой.

## Что отправляется в Gemini

Обработка офисных документов выполняется на устройстве: из DOCX, PPTX, XLSX, EPUB и TXT извлекается до 12 000 символов. Для PDF отправляются первые 3 страницы; для изображений — выбранный файл. Оригинал для публикации не обрезается и не заменяется фрагментом анализа. Сканированные PDF и изображения анализируются самой мультимодальной моделью. Извлечение из офисных файлов ориентировано на текст; для документов, состоящих из картинок, используйте PDF.

Gemini получает фрагмент документа, имя файла и список доступных дисциплин с группами. Список студентов и ключи приложения в запрос не входят. Сервер хранит результат распознавания (включая короткие цитаты) в закрытом кэше, раздельно по аккаунтам. Кэш действителен 7 дней; просроченные записи удаляются при последующих обращениях. Полный отправленный фрагмент не записывается в таблицы анализа, содержимое запросов и ключи не выводятся в журнал. Публикуются только подтверждённые поля и исходный файл. Условия хранения и обработки отправленных данных зависят от настроек и тарифа Google: проверьте их для своего проекта перед передачей документов.

Текст и предложения модели считаются недоверенными данными. Модель не вызывает функции приложения и не назначает права. Выдуманный идентификатор дисциплины отбрасывается, а права проверяются заново сервером при публикации. При недоступности ИИ поля можно заполнить вручную. В демонстрации используется явно обозначенное локальное правило, а не Gemini.

## Подключение рабочего проекта

Ключ Gemini не должен иметь префикс `VITE_`, попадать в репозиторий, `.env.example` или браузерную сборку.

1. Для базы с миграциями 001–015 выполните `supabase/StudyHub_update_v0.31.sql`. Этот файл включает SQL v0.26–v0.28 и миграции 019–020; повторное выполнение допустимо. Если база уже обновлена до v0.28, можно выполнить миграции 019 и 020 по порядку.
2. В Supabase Dashboard → Edge Functions → Secrets задайте `GEMINI_API_KEY`. При необходимости задайте `GEMINI_MODEL`: по умолчанию используется `gemini-2.5-flash`. Проверьте, что выбранная модель доступна вашему ключу и поддерживает PDF, изображения и structured output. `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` предоставляет среда Edge Functions. Служебный ключ используется только сервером для кэша и лимитов; в клиент его добавлять нельзя.
3. В терминале из корня проекта выполните:

```sh
npx supabase login
npx supabase functions deploy material-analyze --project-ref ytrugacimtlxwsmclwlg --use-api
```

Подтвердите аккаунт Supabase в браузере. Проект в команде должен совпадать с проектом URL приложения. Функция дополнительно проверяет аккаунт через Supabase Auth; отключать проверки пользователя для обхода ошибки не нужно.

Если база уже обновлена до v0.30, выполните только `supabase/migrations/202610160020_ai_economy.sql`. После обновления SQL разверните новую версию `material-analyze`: прежняя функция использует старый механизм квот и больше не получит к нему доступ.

4. Опубликуйте новую сборку приложения с обычными `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
5. На реальном аккаунте старосты или преподавателя проверьте один документ: предложение → исправление → подтверждение → открытие материала студентом. До настройки ключа функция возвращает понятное сообщение, а ручная публикация после применения SQL остаётся доступной.

По умолчанию лимит StudyHub — 5 новых анализов на пользователя, 20 на проект в сутки по времени Бишкека, 2 обращения в минуту и 12 000 токенов на минутное окно. Это внутренние предохранители, а не подтверждённые бесплатные квоты Google. Остаток и кнопка его обновления находятся в форме; обновление счётчика не вызывает Gemini. Неудачный вызов провайдера после резервирования также расходует попытку. Действуют дополнительные ограничения Google; бесплатная работа не гарантируется. Лимиты задаются приватной таблицей `material_ai_limits` в миграции 020; владелец проекта может настроить их в SQL Editor. Максимум входа — 8 000 токенов, выхода — 2 048. Перед единственной генерацией выполняется отдельный вызов `countTokens`; если проверка не удалась или бюджет превышен, генерация не запускается. Автоматических повторов и переключения на другие модели нет. После ответа Google 429 действует общая пауза на 2 минуты. Сохранённый результат возвращается до проверки исчерпанного лимита и не вызывает Google. Хеш учитывает полный исходный файл, фрагмент, модель и доступные дисциплины; переименование файла не требует повторной генерации. Изменение прав, содержания или модели делает старый результат неподходящим. Увеличивайте их только после оценки расходов.

## Проверка реализации

`npm test` проверяет базу, права, повторную публикацию, вложение задания, извлечение документа и ограничение PDF первыми тремя страницами. `npm run test:material:intake:browser` проверяет интерфейс на запущенном dev-сервере (по умолчанию порт 5230). `deno check supabase/functions/material-analyze/index.ts` проверяет серверный код, а `npm run test:ai:edge` — авторизацию, квоты, ошибки провайдера и недоверенные ответы на тестовых ответах Gemini, без настоящего API-ключа.

Реальный вызов Gemini и развёртывание в вашем Supabase требуют серверной настройки; локальные тесты их не заменяют.

Для работы исключительно на бесплатном тарифе используйте Google-проект без подключённого биллинга и проверьте доступные квоты выбранной модели в AI Studio. Приложение не может определить по API-ключу, включён ли платный тариф: ограничения StudyHub сами по себе не гарантируют отсутствие начислений в Google-проекте с биллингом.

# Добавление документов с Gemini — v0.30

Помощник находится в «Админ → Дисциплины и преподаватели», в публикациях библиотеки, в материалах дисциплины и на странице «Мои дисциплины» преподавателя. Выберите «Добавить документ с ИИ».

## Сценарий

1. Выберите файл до 10 МБ. Можно посмотреть оригинал до публикации.
2. Разрешите отправить документ в Gemini и нажмите «Распознать документ».
3. Проверьте название, тип и дисциплину. Помощник показывает причину, короткие цитаты и предполагаемую тему. Если дисциплина неизвестна или неоднозначна между группами, её нужно выбрать самостоятельно.
4. Исправьте поля при необходимости и нажмите «Утвердить и опубликовать». Дополнительное подтверждение показывает место публикации.

Лекции, презентации и материалы попадают в выбранную дисциплину. Книги — в общую библиотеку с авторством загрузившего пользователя и группой автора. Преподаватель может публиковать собственные книги, если у него есть действующее назначение в этой группе и доступ к библиотеке; это не даёт ему управление чужими книгами.

Задание создаётся только с правами преподавателя своей дисциплины или владельца. ИИ не назначает срок и максимальный балл: эти поля проверяет человек. Исходный файл прикладывается к заданию и доступен студенту по кнопке «Открыть исходный документ задания». Краткое описание ИИ не заменяет полный оригинал. Прикреплённый файл защищён от удаления как обычный материал. Староста без полномочий преподавателя может распознать такой файл, но не назначить задание.

Сначала создаётся резерв файла, затем выполняются загрузка и подтверждение. Финализация публикации и создание задания выполняются в одной транзакции. Повтор в той же открытой форме использует прежний идентификатор и не создаёт дубликат. Если загрузка не завершена, её можно повторить с теми же полями и файлом; либо удалить незавершённый материал в соответствующем разделе. После перезагрузки формы резерв автоматически не восстанавливается: проверьте незавершённые материалы перед новой отправкой.

## Что отправляется в Gemini

Обработка офисных документов выполняется на устройстве: из DOCX, PPTX, XLSX, EPUB и TXT извлекается до 100 000 символов. Для PDF отправляются первые 20 страниц; для изображений — выбранный файл. Оригинал для публикации не обрезается и не заменяется фрагментом анализа. Сканированные PDF и изображения анализируются самой мультимодальной моделью. Извлечение из офисных файлов ориентировано на текст; для документов, состоящих из картинок, используйте PDF.

Gemini получает фрагмент документа, имя файла и список доступных дисциплин с группами. Список студентов и ключи приложения в запрос не входят. Сервер не сохраняет текст анализа и ответ модели в таблицах и не пишет их в журнал. Публикуются только подтверждённые поля и исходный файл. Условия хранения и обработки отправленных данных зависят от настроек и тарифа Google: проверьте их для своего проекта перед передачей документов.

Текст и предложения модели считаются недоверенными данными. Модель не вызывает функции приложения и не назначает права. Выдуманный идентификатор дисциплины отбрасывается, а права проверяются заново сервером при публикации. При недоступности ИИ поля можно заполнить вручную. В демонстрации используется явно обозначенное локальное правило, а не Gemini.

## Подключение рабочего проекта

Ключ Gemini не должен иметь префикс `VITE_`, попадать в репозиторий, `.env.example` или браузерную сборку.

1. Для базы с миграциями 001–015 выполните `supabase/StudyHub_update_v0.30.sql`. Этот файл включает SQL v0.26–v0.28 и миграцию 019; повторное выполнение допустимо. Если база уже обновлена до v0.28, можно выполнить только `supabase/migrations/202610160019_material_intake.sql`.
2. В Supabase Dashboard → Edge Functions → Secrets задайте `GEMINI_API_KEY`. При необходимости задайте `GEMINI_MODEL`: по умолчанию используется `gemini-2.5-flash`. Проверьте, что выбранная модель доступна вашему ключу и поддерживает PDF, изображения и structured output. `SUPABASE_URL` и `SUPABASE_ANON_KEY` предоставляет среда Edge Functions.
3. В терминале из корня проекта выполните:

```sh
npx supabase login
npx supabase functions deploy material-analyze --project-ref ytrugacimtlxwsmclwlg --use-api
```

Подтвердите аккаунт Supabase в браузере. Проект в команде должен совпадать с проектом URL приложения. Функция дополнительно проверяет аккаунт через Supabase Auth; отключать проверки пользователя для обхода ошибки не нужно.

4. Опубликуйте новую сборку приложения с обычными `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
5. На реальном аккаунте старосты или преподавателя проверьте один документ: предложение → исправление → подтверждение → открытие материала студентом. До настройки ключа функция возвращает понятное сообщение, а ручная публикация после применения SQL остаётся доступной.

Серверный лимит — 10 анализов на пользователя и 100 на весь проект в сутки по времени Бишкека. Неудачный вызов провайдера после резервирования также расходует попытку. Действуют дополнительные ограничения Google; бесплатная работа не гарантируется. Лимиты задаются функцией `begin_material_analysis` в миграции 019. Увеличивайте их только после оценки расходов.

## Проверка реализации

`npm test` проверяет базу, права, повторную публикацию, вложение задания, извлечение документа и ограничение PDF первыми 20 страницами. `npm run test:material:intake:browser` проверяет интерфейс на запущенном dev-сервере (по умолчанию порт 5230). `deno check supabase/functions/material-analyze/index.ts` проверяет серверный код, а `npm run test:ai:edge` — авторизацию, квоты, ошибки провайдера и недоверенные ответы на тестовых ответах Gemini, без настоящего API-ключа.

Реальный вызов Gemini и развёртывание в вашем Supabase требуют серверной настройки; локальные тесты их не заменяют.

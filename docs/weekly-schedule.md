# Недельное расписание · v0.45

> Справка отдельного этапа. Версии и результаты проверок ниже относятся к моменту его разработки. Текущие настройки — в [README](../README.md) и [развёртывании](deployment-current.md), подтверждённые результаты — в [готовности пилота](pilot-readiness.md).

Владелец: Админ → Расписание → группа. Староста: Админ → Расписание; группа уже определена его полномочиями. Для каждого дня недели заполните пары, выбрав существующие дисциплины. Указываются только начало, конец и необязательная аудитория. Пары сортируются по времени. Обратные интервалы, дубликаты идентификаторов, чужие дисциплины и пересечения внутри шаблона отклоняются на сервере атомарно.

Шаблон действует с недели создания, без конечной даты. Изменения шаблона отражаются во всех его повторениях. Удаление пары из шаблона удаляет её повторения и исключения. Для одного занятия используйте «Изменения на отдельную дату»: выберите дату и пару, измените время, дисциплину или аудиторию либо отмените занятие. «Вернуть обычное расписание» удаляет исключение. Новое время и восстановление проверяются на пересечения. Изменение шаблона также не может создать пересечение с уже сохранённым исключением.

Старые записи group_board остаются занятиями на конкретные даты. Они не преобразуются в недельный шаблон автоматически: иначе одинаковые записи могут оказаться разными реальными занятиями. Они доступны в списке изменений на выбранную дату для правки или удаления. При совпадении времени старой записи и нового шаблона студент видит предупреждение о пересечении; удалите ненужную прежнюю запись. Пары нового шаблона проверяются между собой при сохранении.

Студент видит свою зарегистрированную группу и один день с полоской Пн–Вс. Начальный день — сегодня по Бишкеку (UTC+6). Другая дата и кнопки недель позволяют просматривать будущие занятия. Выбранная дата восстанавливается после перезагрузки. Нажатие на действующую пару открывает материалы дисциплины. Отменённая пара остаётся видимой с отметкой, но не используется как текущая или следующая и не экспортируется с напоминанием. Дополнительные действия (обновление и ICS выбранного дня) свёрнуты.

## Установка и проверка

Для существующей базы v0.35+ выполните `supabase/StudyHub_update_v0.45.sql`. Патч включает v0.42/v0.43; не используйте его для пустого проекта. Для установки с миграций добавлена `202610170024_weekly_schedule.sql`. Проверено повторное применение и сохранение существующих заметок. Административных реквизитов живой базы в среде нет, поэтому её обновляет владелец проекта в SQL Editor.

RPC `schedule_catalog` объединяет прежние занятия и вычисляемые повторения. Все даты хранятся и расширяются по Asia/Bishkek; наружу выдаются UTC timestamptz, порциями по 50. Доступ проверяется для группы и исходной/заменяющей дисциплины. Закрытые и архивные предметы не раскрываются. Прямой доступ к таблицам шаблонов и исключений закрыт; сохранять могут только действующий староста своей группы и владелец с доступом к расписанию. При отсутствии нового RPC клиент использует прежний каталог для чтения.

Запись дня использует версию и идентификатор запроса. Повтор после потери ответа безопасен, а старый черновик после перезагрузки не перезаписывает более свежий день. Черновик и версия остаются в этой вкладке, привязаны к аккаунту, группе и дню. Конфликт требует явного обновления с подтверждением удаления своего черновика. Проверки: `npm test`, `npm run test:weekly:schedule:browser`; тесты расписания, синхронизации и навигации используют их переменные `*_TEST_URL` для запущенного Vite.

Не реализованы чётные/нечётные недели, каникулы, конечная дата семестра и перенос одной пары на другой день недели. Исключение меняет занятие внутри выбранной даты. Это отдельные расширения, не влияющие на простой основной сценарий.

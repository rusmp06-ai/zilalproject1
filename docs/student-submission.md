# Черновики ответов студента — v0.32

> Справка отдельного этапа. Версии и результаты проверок ниже относятся к моменту его разработки. Текущие настройки — в [README](../README.md) и [развёртывании](deployment-current.md), подтверждённые результаты — в [готовности пилота](pilot-readiness.md).

Текст ответа автоматически сохраняется на устройстве через 300 мс после изменения. При переходе в другой раздел, смене задания, перезагрузке или уходе вкладки в фон выполняется немедленная попытка сохранения. Статус под заголовком формы показывает сохранение, успешную запись или ошибку.

Черновики разделены по демонстрационному/рабочему режиму, аккаунту, заданию и номеру попытки. Чужой аккаунт и другая попытка не подставляют прежний текст. После возврата работы на доработку начинается отдельная попытка с собственным черновиком. Учёт последней своей попытки не зависит от страницы истории сдач.

Это локальные черновики, не отправленные преподавателю. Они не переносятся на другое устройство. Очистка данных сайта удаляет сохранённый текст; общий компьютер следует использовать только под своим аккаунтом. Выход из аккаунта не стирает незавершённую работу: она снова доступна после входа в тот же аккаунт на этом устройстве.

Выбранный файл удерживается в памяти вкладки при переходах внутри приложения. Чтобы не перегружать устройство, в памяти остаются не более пяти таких файлов. В хранилище черновика записываются только имя, размер и тип вложения. После перезагрузки, закрытия вкладки или освобождения файловой памяти нужно прикрепить файл повторно; форма показывает его имя и блокирует отправку с потерянным вложением. Убрать напоминание и отправить один текст можно только явным действием «Продолжить без этого файла».

При отсутствии интернета можно продолжать писать в уже открытой форме; отправка недоступна до восстановления соединения. После полного перезапуска для открытия задания и проверки аккаунта может потребоваться интернет; локально сохранённый текст при этом остаётся на устройстве. При ошибке сохранения показываются предупреждение и кнопка повторной записи. Перед переходом в другой раздел приложение пытается сохранить ответ; если это не удалось, требуется подтверждение. Пока текст остался только в памяти, не закрывайте вкладку.

Обнаруженное изменение черновика в другой вкладке не заменяет текущий текст автоматически: пользователь выбирает, какую версию принять. На время отправки переходы через меню блокируются. После подтверждённого `submit` содержимое черновика очищается и сохраняется отметка успешной отправки; ошибка обновления списка попыток не превращает эту отправку в повторную. Отметка относится только к конкретной попытке. Локальная очистка не удаляет более новую версию, обнаруженную в другой вкладке.

Новых SQL и серверных вызовов для автосохранения нет. Серверные права, сроки, квоты файлов и запрет лишней сдачи продолжают проверяться существующими RPC. Обновите приложение и перезапустите локальный сервер или опубликуйте новую сборку.

Проверки: `npm test`; `npm run test:submission:draft:browser` на dev-сервере порта 5260 либо с `SUBMISSION_DRAFT_TEST_URL`. Проверяются переход до задержки сохранения, восстановление, разные аккаунты/задания/попытки, ошибка локального хранилища, конфликт вкладок, отсутствие сети, ошибка отправки, подтверждение при неудачном обновлении списка и повторная сдача.

Собранная версия дополнительно проверяется `node tests/submission-draft-production.browser.mjs` на preview-сервере порта 4260 (либо через `SUBMISSION_PRODUCTION_URL`) без импорта исходных модулей в браузер.

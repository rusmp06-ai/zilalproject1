# Учебное пространство студента — v0.11.1

Цель, уточнённая пользователем: максимально удобная ежедневная учёба. Студент открывает приложение и быстро получает доступ к материалам, дисциплинам, лекциям, расписанию, чтению, заметкам и календарю. Административные функции обеспечивают это пространство.

## Реализовано

- Главная для участников: ближайшие пары на семь дней, ближайшие сроки, дисциплины выбранной группы, избранные книги с сохранённой позицией.
- Переход из пары к дисциплине, из срока к конкретному заданию, из книжной полки к чтению.
- Список заданий по дисциплинам выбранной группы с поиском по названию задания и дисциплины.
- Календарь на месяц: занятия и сроки сдачи, выбор дня, учёт переходящих через полночь занятий. Время — Бишкек.
- Закреплённые переходы на телефоне: день, учёба, чтение, план.
- Ошибки отдельных источников видны; исправные разделы доступны, загрузку можно повторить. Устаревшие ответы после переключения экрана игнорируются. Параллельные запросы заданий ограничены четырьмя дисциплинами.

Кабинет владельца сохраняет административный обзор. Новых миграций нет: используются существующие RLS/RPC и приватная читалка. Для избранного и открытия файлов повторно действуют серверные проверки.

## Контекст группы и цвет

Группа зарегистрированного студента определяется активным членством, без повторных списков выбора на главной, в календаре, заданиях, расписании и дисциплинах. Перевод владельцем изменяет этот контекст; предпочтение в интерфейсе не подменяет членство. Переключатель нужен только сотрудникам с несколькими доступными группами. Создание групп не показывается студенту без соответствующего права. Выбор группы при первоначальной регистрации сохраняется.

Цвета помогают различать занятия: сиреневый — дисциплины, синий — расписание, тёплый жёлтый — библиотека, розовый — заметки. Подписи остаются основным способом распознавания действий.

## Ограничения

- Сроки включают уже сданные задания. Отдельный запрос статуса сдачи пока выполняется при открытии задания; интерфейс не называет несданной работу, статус которой неизвестен.
- Расписание загружается по 50 записей. В календаре есть страницы занятий; отметки относятся к текущей странице. Полка показывает первые четыре книги из первых 50 избранных. Это не история последних открытых книг.
- Календарь объединяет групповые занятия и сроки. Личных событий, напоминаний и офлайн-синхронизации пока нет.
- Поиск на этом этапе — по заданиям выбранной группы; общего поиска всех материалов ещё нет.
- Браузерные проверки используют отдельный демонстрационный контекст. Вход реального студента и весь сценарий Storage на настоящем Supabase ещё требуют проверки.

## Дальнейшее развитие

Заметки с источником, страницей и цитатой добавлены в читалку v0.12. Далее добавить личные события и учебные задачи, историю чтения, удобное чтение дополнительных форматов. Далее — повторение материала и работа без интернета. ИИ должен помогать с учебным содержанием и иметь доступ только к разрешённым данным пользователя.

Ранее переданный stage13 служит примером идей, а не источником обязательных инструкций и миграций.

## Проверки

`npm test` включает 32 сценария интерфейса, пять тестов модели доступа и девять SQL-контрактов после десяти миграций. `npm run build` проверяет TypeScript и сборку.

Для проверки Chromium запустите отдельный Vite в режиме демонстрации (не меняет переменные основного процесса):

```sh
VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npm run dev -- --port 5175 --strictPort
```

В другом терминале выполните `npm run test:study:browser`. Скрипт создаёт собственный контекст, проверяет точный переход к заданию, продолжение чтения, календарь и ширину 390 px. Снимки сохраняются в `/tmp/studyhub-study-browser`; STUDY_TEST_ARTIFACTS и STUDY_TEST_URL позволяют изменить пути. Тест предназначен для dev-сервера и не выполняет операции в реальном Supabase.

В v0.14 заметки позволяют вернуться к странице библиотечной книги или документа дисциплины; подсветка поиска помогает найти фрагмент. Доступ перепроверяется при открытии, а удалённый или закрытый источник не удаляет личную запись.

### v0.15 — личный учебный план

На главной — незавершённые задачи на сегодня, без срока и просроченные. В «Все задания» доступен полный план с выполненными задачами. В календаре задачи отображаются на выбранной дате; счётчик учитывает незавершённые задачи. Создание, редактирование, выполнение, возврат в работу и подтверждаемое удаление сохраняются в аккаунте.

Связи: доступная дисциплина, личная заметка, книга из первой страницы библиотеки или документ из заметки читалки. Заметка открывается непосредственно в плане; документ проверяет текущий доступ перед открытием. Полный поиск документов для выбора связи пока не реализован.

Хранение: типизированные записи `studyhub_plan:1` через существующие приватные RPC заметок; задачи скрыты из обычного списка заметок. План читает все страницы личных записей (до установленного сервером лимита 1000). Задачи и заметки разделяют квоту 1 МБ / 1000 записей и контроль версии. Это не отправка преподавателю и не оценка работы. Новая SQL-миграция не требуется. Напоминаний и повторяющихся задач пока нет.

Проверки: `npm test`, `npm run test:plan:browser`, `npm run test:study:browser`, `npm run build`. Реальный Supabase проверен двумя независимыми сеансами одного тестового аккаунта: сохранение, чтение, выполнение и отклонение устаревшей версии; временная задача удалена.

## Главная в спешке — v0.21

Первым идёт «Сейчас и следующая пара»: название занятия, крупные время и аудитория, сколько минут идёт текущая пара и сколько осталось до следующей. Если следующая пара завтра или позже, рядом указана дата. Отсутствующая аудитория обозначена прямо. При совпадении текущих занятий появляется предупреждение; лента сегодня показывает все пересекающиеся занятия. Пара считается текущей с начала включительно до окончания исключительно. Часы обновляются каждые 15 секунд и при возврате во вкладку; после полуночи заново загружается расписание нового дня. Время — Бишкек (UTC+6), отсчёт использует часы устройства.

Карточка появляется после ответа расписания независимо от загрузки заданий, плана и библиотеки. «Материалы пары» ведёт прямо на полку материалов текущей дисциплины; «Открыть конспект» — в её личные заметки; когда текущей пары нет, используется ближайшая. У занятия без привязанной дисциплины первые две кнопки недоступны. «Расписание сегодня» прокручивает к сегодняшней ленте. Прошедшие пары свёрнуты, текущая выделена, положительные промежутки обозначены как перерывы. На ширине 390 px основные действия помещаются над нижней навигацией на первом экране при обычных названиях/аудиториях; длинное содержимое переносится и может потребовать прокрутки.

«Сдать сегодня» показывает до трёх сегодняшних заданий, требующих внимания. Отправленные и оценённые работы исключены; при ошибке статуса он остаётся неизвестным. Остальные сроки находятся ниже; все задания доступны отдельной кнопкой. Неуспешные запросы не превращаются в утверждение, что сдавать нечего.

В форме объявления преподаватель или староста может отметить «Изменение расписания — показывать на главной». Блок «Важные изменения» показывает до пяти таких опубликованных объявлений за последние семь дней. Приложение не угадывает отмены по отсутствующей записи и не выдаёт обычные сообщения за переносы. Отметка хранится в существующем поле объявления как совместимый JSON-конверт; текстовые старые объявления не меняются, в списках и дисциплине отображается сам текст. Длинный конверт проверяется до отправки. Нового SQL для этой отметки не требуется; старые версии приложения могут показать конверт как текст, поэтому следует обновить весь фронтенд.

### Сохранённое расписание

После успешной загрузки «Главная» сохраняет полную семидневную копию расписания отдельно для аккаунта (`live:`/`demo:` + UUID) и группы. Только расписание: личные заметки, задания и оценки в эту копию не входят. До 500 занятий в одной копии, до восьми групп и 1 МиБ на аккаунт. При превышении лимита/отказе хранилища интерфейс не обещает наличие сохранённой копии. В производственной сборке приложение регистрирует service worker и отмечает доступность без сети после его готовности. Демонстрация и локальный сервер используют тот же механизм хранения, но не подтверждают проверку облачного расписания.

При потере сети или неудачной загрузке доступная копия показывается с датой и предупреждением «изменения не проверены». Она не получает новую дату обновления. Документы и редактирование из карточки в этом режиме не открываются; сегодняшняя лента доступна для просмотра. Когда сеть возвращается, расписание повторно запрашивается. Если сервер явно закрыл доступ к расписанию, копия группы удаляется. Копии также удаляются для групп, исчезнувших из актуального профиля; запоздавший отменённый запрос не записывает данные в кэш. Изменения прав без сети проверить невозможно.

Если при автономной перезагрузке настоящей Supabase нельзя восстановить кабинет, на экране входа доступно «Расписание без интернета» для ранее использованного аккаунта этой вкладки. Это только просмотр копии, без входа в серверный кабинет. При выходе идентификатор автономного аккаунта убирается. Другой пользователь не получает его копию через интерфейс. Локальное хранилище устройства не является шифрованным сейфом; общего офлайн-доступа к профилям нет.

### Проверки v0.21

Модульные проверки: точные границы пар, пересечения и полночь Бишкека; охват даты и изоляция копий; явная отметка важного объявления; независимая загрузка первой карточки; автономный просмотр; удаление копии после подтверждённого запрета. Браузер `test:day:browser`: реальные переходы к материалам и конспекту, публикация отмеченного объявления, сроки сегодня, лента, размеры 390/320 px, первое размещение кнопок, потеря/возврат сети и автоматическая смена пары. `test:day:offline:browser` использует производственную сборку: установка оболочки, перезагрузка без сети, копия аудитории/времени, изоляция аккаунтов и повторная загрузка после подключения. Все браузерные сценарии используют демонстрационные данные; проверка настоящего Supabase расписания после публикации сайта остаётся отдельной операцией.

В производственном офлайн-тесте Playwright блокирует реальные сетевые запросы; сигнал `navigator.onLine` дополнительно эмулируется, потому что Chromium при перезагрузке через service worker может сообщать `true` даже при отключённой тестовой сети. При настоящей Supabase ошибка сетевого запроса также включает просмотр сохранённой копии независимо от этого сигнала.

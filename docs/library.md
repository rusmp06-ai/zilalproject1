# Общая библиотека — v0.4

> Справка отдельного этапа. Версии и результаты проверок ниже относятся к моменту его разработки. Текущие настройки — в [README](../README.md) и [развёртывании](deployment-current.md), подтверждённые результаты — в [готовности пилота](pilot-readiness.md).

## Возможности

Все разрешённые участники читают и скачивают опубликованные материалы независимо от группы автора. Староста публикует материалы от своей группы, меняет название и удаляет только собственные публикации. Владелец управляет всеми публикациями. Преподаватель без дополнительной роли старосты не загружает материалы в общую библиотеку.

Каталог: поиск по названию и имени файла, 50 записей на страницу, автор, группа и дата. TXT и PDF открываются в читалке; изображения — в окне просмотра. DOCX, PPTX, XLSX доступны для скачивания. Читалка с прогрессом, закладками и избранным добавлена в [v0.9](reader.md). Конвертация офисных форматов остаётся отдельным этапом.

## Файлы и бюджет

Поддерживаются PDF, TXT, JPEG, PNG, WebP, DOCX, PPTX, XLSX. Лимит файла — 10 МиБ (в интерфейсе «10 МБ»). Бюджет по таблице файлов — 800 МиБ, чтобы оставить запас в бесплатном хранилище. Эти лимиты — настройки пилота, а не обещание бесплатного неограниченного хранения. Месячная передача данных этим счётчиком не измеряется; её нужно контролировать отдельно в Supabase.

Перед загрузкой создаётся резервирование. Пока оно не опубликовано, в бюджете учитывается полный максимальный размер файла, даже если клиент заявил один байт. Резервирования сериализованы advisory lock; у пользователя может быть только одна незавершённая загрузка.

Storage принимает файл в уникальный путь, без upsert и без разрешения UPDATE. После загрузки сервер проверяет размер и MIME в метаданных Storage и публикует материал. MIME не является проверкой содержимого: антивирус и серверная конвертация ещё не реализованы.

Если загрузка оборвалась, автор или владелец видит незавершённую карточку. Её нужно удалить перед повторной загрузкой. Незавершённые загрузки не очищаются автоматически.

## Удаление

1. RPC begin_library_delete закрывает публикацию и разрешает удаление объекта управомоченному пользователю.
2. Клиент вызывает Storage API remove.
3. RPC finish_library_delete проверяет отсутствие объекта и удаляет записи публикации и файла.

SQL не удаляет storage.objects напрямую: реальные байты удаляет Storage API. При ошибке карточка остаётся в состоянии удаления для повторной попытки. Операции записываются в аудит.

## Доступ

Бакет studyhub-library приватный. Чтение объекта проверяется RLS, включая запреты библиотеки для пользователя и его групп, блокировки аккаунта и отсутствие активных групп. Владелец обходит групповые ограничения для администрирования. К файлу нельзя получить доступ просто по публичному URL.

Приложение скачивает объект с авторизацией и показывает Blob URL внутри текущего браузера. Долгоживущие подписанные ссылки интерфейс не создаёт. Уже скачанные/показанные байты отозвать невозможно. Пользователь с разрешённым чтением технически может вызвать доступные ему операции Storage вне интерфейса; не следует обещать запрет копирования файлов.

Проверки предполагают новый проект без других разрешающих политик Storage для этого бакета. Перед настоящим запуском проверить политики в Supabase.

## Демонстрация

Файлы сохраняются в IndexedDB, метаданные — в localStorage. Когда браузер запрещает эти хранилища, используется память до перезагрузки. Смена демонстрационной роли работает только локально. Данные не отправляются настоящим студентам. Сброс демонстрации удаляет её загруженные файлы.

## Проверки и границы

PGlite проверяет схему, RPC и RLS. Тесты имитируют таблицы Storage и его метаданные; они не проверяют реальную загрузку байтов, сервисный HTTP-протокол или квоты Supabase.

Проверены чужие изменения и удаления, студенческая загрузка, запреты чтения объекта, восстановление доступа, публикация без объекта и с неверным размером, общий бюджет, лимит одного резервирования, многошаговое удаление.

jsdom проверяет загрузку в демонстрации, чтение без прав изменения у студента, удаление владельцем и валидацию файлов. Настоящий браузер, IndexedDB и Supabase Storage ещё требуют проверки.

## Мир библиотеки v0.18

Библиотека стала книжной витриной: адаптивная сетка обложек, собственная спокойная палитра, поисковая строка и полки. Полка «Читаю» содержит опубликованные документы с сохранённым прогрессом и непрочитанными страницами; прочитанные и одностраничные документы туда не входят. «Избранное» использует существующие личные отметки аккаунта; на обложке показана звезда. Формат и сортировка работают по всему загруженному каталогу, а не только по первой серверной странице. На экране 24 карточки; число материалов относится к текущей полке и фильтрам, не является общим счётчиком базы.

Каталог загружается метаданными последовательными страницами по 50 записей, максимум 5000. Сами файлы для показа обложек не скачиваются. При отказе доступа на следующей странице весь ранее полученный список скрывается. Ошибка загрузки не выдаётся за полный каталог; для очень больших каталогов предлагается уточнить поиск. Права и ограничения сервера сохранены.

Обложки — типографическое оформление на основе реального названия и формата. Это не оригинальные обложки издательств. Цвет стабилен для каждого материала; длинные названия набираются мельче. Издательский автор и рейтинг не выдумываются: имя пользователя обозначено «Добавил». Изображения/импорт настоящих обложек и предметные категории потребуют отдельного хранения и пока не реализованы.

Нажатие обложки или «Открыть» запускает существующую читалку. «Действия» раскрывает скачивание, автономное сохранение и переключение избранного. Управление публикацией доступно только прежним разрешённым ролям; незавершённые загрузки/удаления остаются видимыми для восстановления. Форма загрузки и квота находятся ниже витрины; кнопка «Добавить материал» переносит к форме. Сервисные данные не занимают начало студенческой страницы.

Проверены все страницы каталога (включая 51-й материал), фильтры и сортировка, отказ доступа/ошибка на следующей странице, полки, поиск, переход через обложку, мобильная ширина 390/320 px и существующая читалка. Новой миграции для v0.18 нет. Скриншоты браузерного сценария используют отдельные тестовые книги, не добавляют их в настоящую Supabase.

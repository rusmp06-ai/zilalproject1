# StudyHub · v0.46.0

Учебное пространство: дисциплины и материалы, расписание, задания, библиотека и личные заметки. Пилот — 60 студентов четырёх групп. Новые функции приостановлены до проверки основного учебного сценария.

## Запуск

Поддерживаются Node **22.22.2+ в ветке 22**, **24.15+ в ветке 24** и 26+. Для воспроизводимой проверки CI использует 22.22.2 и 24.19.0.

```sh
npm ci
npm run dev
```

Для своего Supabase скопируйте `.env.example` в `.env` и заполните публичные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Ключ `service_role` в браузер не помещать. Без подключения можно открыть демонстрацию через `?demo=1`; её данные находятся только в этом браузере.

```sh
npm run build       # typecheck + production dist/
npm run build:budget
npm run build:preview # создаёт локальный preview.html без записи в Git
```

Автономная демонстрация — отдельная сборка. Команда автоматически очищает обе переменные `VITE_SUPABASE_*` в дочернем процессе сборки. `preview.html` создаётся по запросу и не хранится в репозитории; CI прикладывает его как артефакт сборки. На хостинг публикуется `dist/` обычной production-сборки.

## База данных

**Единственный источник SQL — `supabase/migrations/`.** Файлы `StudyHub_update_*.sql` и `StudyHub_upgrade_*.sql` генерируются автоматически и проверяются в CI. Их не редактируют вручную.

```sh
npm run sql:generate
npm run sql:check
```

Для существующей StudyHub с базовыми миграциями 001–010 доступен накопительный [StudyHub_upgrade_latest.sql](supabase/StudyHub_upgrade_latest.sql). Он транзакционный, повторяемый и проверен на совпадение схемы, прав, политик, индексов и функций с полной цепочкой миграций. Это **не установщик для пустой базы**. Порядок установки и учёт ручных обновлений: [процесс базы](docs/database-workflow.md).

## Вход и роли

Подтверждение email **оставляем включённым**. В Supabase Auth укажите адрес приложения в Site URL и Redirect URLs для подтверждения и восстановления пароля. Новый студент регистрируется, подтверждает почту и входит. Выбор группы без приглашения создаёт заявку; закрытые материалы доступны после одобрения. Приглашение определяет группу и полномочия на сервере. Студент повторно свою группу не выбирает.

Староста учится в обычном студенческом кабинете; управление находится в «Админ». Он управляет только разрешёнными ему группами. Оценивать работы может назначенный преподаватель. Владелец не читает чужие личные заметки. Доступ обеспечивают RLS и RPC, а не скрытие кнопок.

## Проверки

```sh
npm run format:check
npm run sql:check
npm test                      # все Node/SQL/UI-наборы; общий отчёт, не прерывается на первом сбое
npm run test:browser:smoke     # основные сценарии; сам запускает и останавливает Vite
npm run test:browser           # полный браузерный набор для dev-сборки
npm run build
npm run test:browser:offline   # production-проверки кеша и чтения без сети
npm run test:ai:edge           # Deno 2.7.1, без вызовов Gemini
npm run verify                # полный локальный прогон, включая браузер и edge
```

Для браузера установите Chromium: `npx playwright-core install --with-deps chromium`. Можно задать `CHROMIUM_PATH`. Для edge-тестов нужен Deno 2.7.1. Отчёты сохраняются в `test-results/`, каталог не входит в Git.

[CI](.github/workflows/quality.yml) проверяет Node 22/24, стиль, SQL, типы, сборку, бюджет загрузки, основные браузерные сценарии, офлайн-режим и edge-функцию. Полный браузерный набор запускается еженедельно и вручную через Actions. Тесты CI используют локальный PostgreSQL-совместимый PGlite и демо; это не проверка живой базы.

## Дополнительные инструменты

ИИ-анализ, OCR и оптимизация PDF остаются опциональными. Ручная публикация работает без Gemini. Тяжёлые модули загружаются по запросу; OCR и оптимизатор не скачиваются при сохранении обычной книги для чтения без сети.

ИИ-ключ хранится только в Supabase Edge Function. Перед её публикацией задайте `ALLOWED_ORIGINS` — точные адреса разрешённых сайтов через запятую, например `https://studyhub.example`. Wildcard CORS удалён. Требуются также серверные параметры Gemini и Supabase; подробности: [развёртывание](docs/deployment-current.md).

## Готовность пилота

Автоматические проверки не заменяют регистрацию нового студента, доставку письма, проверку на физических телефонах и занятия реальной группы. Актуальные доказательства и оставшиеся шаги ведутся в [готовности пилота](docs/pilot-readiness.md). Исторические записи находятся в `docs/history/`; они не определяют текущие настройки.

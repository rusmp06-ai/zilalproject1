# StudyHub 2.0 — v0.34.0

Учебная платформа для 60 студентов четырёх групп. Бюджет пилота — 0.

## Посмотреть интерфейс

В архиве есть **preview.html** — демонстрация в одном файле. Откройте его в обычном браузере; внешний сервер не требуется. Если просмотрщик телефона не выполняет JavaScript, откройте файл в браузере либо используйте локальный запуск ниже.

Верхняя панель переключает демонстрационные роли. Данные сохраняются только в этом браузере; если браузер запрещает локальное хранение, они живут до перезагрузки. Пригласительные ссылки демонстрации работают только там, где сохранены эти данные. Не используйте демонстрацию для настоящих студентов.

## Локальный запуск

Публикация сайта через GitHub и Netlify: [инструкция](docs/netlify.md). Настройки сборки сохранены в `netlify.toml`; публичные параметры Supabase задаются в Netlify перед сборкой.

Node.js 24.15+ в ветке 24 (проверено на 24.19), npm:

```sh
npm ci
npm run dev
```

Откройте адрес, который покажет Vite. Без переменных окружения работает демонстрация.

```sh
npm test
npm run build
npm run build:preview
```

## Подключение Supabase

Для нового развёртывания:

1. Создайте новый тестовый проект Supabase.
2. Примените SQL из supabase/migrations по порядку.
3. Подтверждение email можно оставить включённым. Укажите адрес опубликованного приложения в Supabase Auth → URL Configuration (Site URL и разрешённые Redirect URLs) для подтверждения регистрации и восстановления пароля.
4. Скопируйте .env.example в .env, задайте публичные VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY. Никогда не используйте service_role в браузере.
5. Зарегистрируйте собственный аккаунт. В доверенном SQL Editor добавьте его UUID в platform_owners. До этого аккаунт не является владельцем.
6. Перезапустите Vite. Проверьте сценарии на тестовых пользователях до реального запуска.

Публичный ключ не заменяет серверные права: чтение защищено RLS, изменения — проверенными RPC. Владелец не назначается из данных регистрации.

## Сохранность ответов студента v0.32

Ответ автоматически сохраняется на устройстве отдельно для аккаунта, задания и попытки. Текст восстанавливается после переходов и перезагрузки. Есть статус сохранения, предупреждения об ошибке и конфликте вкладок, напоминание повторно прикрепить файл. Ошибка отправки сохраняет черновик; подтверждённая отправка очищает его даже при сбое обновления списка работ. Нового SQL не требуется. [Подробности и ограничения](docs/student-submission.md).

## Экономия Gemini v0.31

Повторное распознавание того же файла берётся из закрытого кэша без обращения к Google. В форме видны остатки лимита StudyHub; счётчик можно обновить без Gemini. Анализ ограничен первыми 3 страницами PDF или 12 000 символами текста; перед генерацией проверяются токены. Предусмотрены дневные и минутные лимиты, общий бюджет токенов и пауза после Google 429. Ручная публикация работает при недоступности ИИ.

Нужны [SQL v0.31](supabase/StudyHub_update_v0.31.sql) и повторное развёртывание `material-analyze`. Внутренние лимиты не заменяют квоты Google и не отключают его биллинг: для бесплатного использования нужен соответствующий Google-проект. [Подключение и ограничения](docs/material-intake.md).

## Добавление документов с ИИ v0.30

Помощник Gemini предлагает тип, название и дисциплину документа; человек проверяет оригинал, исправляет поля и подтверждает публикацию. Лекции идут в дисциплину, книги — в библиотеку, задания создаются с приложенным исходником. Права проверяются на сервере, неоднозначные дисциплины требуют уточнения. При недоступности ИИ остаётся ручное заполнение.

Для работы нужны [SQL v0.30](supabase/StudyHub_update_v0.30.sql), серверная функция `material-analyze` и секрет `GEMINI_API_KEY` в Supabase. Ключ не включается в приложение. [Подключение и ограничения](docs/material-intake.md). В демонстрации Gemini заменён явно обозначенным локальным правилом.

## Оптимизация PDF v0.29

## Что работает на этом этапе

React + TypeScript + Vite; адаптивные формы входа и регистрации; обзор групп; создание группы и дисциплин; приглашения студентов, старост и преподавателей; принятие приглашения существующим аккаунтом; панель блокировок пользователей, групп и разделов; восстановление доступа; общая библиотека с загрузками, поиском, просмотром и удалением; разделы лекций, презентаций и материалов внутри дисциплин с текстом и файлами; задания с текстовыми условиями, сдача работ текстом и файлом, черновики и публикация оценок, возврат на доработку с историей попыток; расписание на выбранные семь дней и объявления группы с созданием, изменением и удалением; личные заметки с поиском и защитой от перезаписи устаревшей версии; Supabase-адаптер и отдельная локальная демонстрация; читалка PDF/TXT/DOCX/EPUB в библиотеке и дисциплинах: поиск, оглавление, темы, размер текста, масштаб PDF, позиция, закладки, избранное и личные заметки с цитатами. Подробности: [читалка](docs/reader.md).

## Проверено

Сборка и TypeScript, пять тестов модели прав, тринадцать миграций и контракты доступа в PGlite, 40 тестов интерфейса и валидации в jsdom. jsdom проверяет взаимодействия, но не отображение CSS. PDF, настоящий DOCX, поиск, цитирование, темы и чтение файлов дисциплин проверены в Chromium, включая мобильную ширину; полный визуальный аудит интерфейса ещё не выполнен. Настоящие Auth/Storage и отметки дополнительно проверены отдельным интеграционным сценарием; PGlite использует имитацию Storage.

В текущей облачной среде публичные параметры тестового Supabase уже заданы; проверены Auth settings и каталог групп. Реальный вход, байты Storage и передача отметок между двумя независимыми сессиями одного аккаунта проверены. Интерфейс на двух физических устройствах и отдельный студенческий аккаунт в настоящей базе пока не проверены. Отметки библиотеки и дисциплин используют аккаунт. В текущей базе [миграция 010](supabase/migrations/202610110010_course_reader.sql) уже применена. Для других баз без неё курсовая читалка явно сохраняет прежний локальный режим.

Автоматическая проверка настоящей синхронизации подготовлена: `npm run test:course:sync`. Для неё нужны данные подтверждённого тестового аккаунта в настройках среды (подробности в [документации читалки](docs/reader.md#автоматическая-проверка-настоящего-supabase)); с данными тестового аккаунта проверка прошла 11 октября 2026 года.

### v0.22 · расписание студента

Раздел «Расписание» показывает день или календарную неделю с понедельника.
Группа студента подставляется из профиля. Карточки показывают время (Бишкек),
аудиторию, текущую пару, перерывы и пересечения; подробности ведут к материалам
и личным заметкам дисциплины. Выбранный период можно экспортировать в ICS
с напоминаниями за 30 минут. Импортированный календарь не синхронизируется автоматически.
Управление доступно владельцу и действующему старосте своей группы и открывается отдельно.
SQL для этого обновления не нужен; отмены, исключения повторений и история переносов
пока не добавлены. Сохранённое расписание без сети остаётся доступно через «Главная».

Проверка браузера: запустите `VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npm run dev -- --port 5201`,
затем `npm run test:schedule:browser` (при другом адресе задайте `SCHEDULE_TEST_URL`).

### v0.23 · староста учится как студент

Учебный кабинет старосты использует его зарегистрированную студенческую группу
(если есть), иначе группу его старостинского членства. На главной — пары и личные
задания; в дисциплинах — чтение, собственные сдачи, прогресс и заметки.
Формы публикации и управления перенесены в отдельную панель «Админ», доступную
из бокового меню и кнопкой в шапке, в том числе на телефоне. Возвращение к учёбе
сохраняет текущий аккаунт и личные данные.

«Админ» содержит участников, дисциплины и назначения преподавателей, расписание,
объявления, публикации в библиотеке и приглашения. Управляемые группы ограничены
действующими членствами старосты; права преподавателя в другой группе не добавляют
её в эту панель. Создание новой группы доступно только при выданном владельцем лимите.
Староста не получает права выставлять оценки, читать чужие работы и личные записи,
блокировать аккаунты или переносить студентов. Проверки существующих серверных прав
сохраняются. Кабинеты владельца и преподавателя пока сохраняют прежнюю структуру.

Для **имён и ролей участников** выполните `supabase/StudyHub_update_v0.23.sql`
в Supabase SQL Editor после ранее установленных миграций. Этот короткий повторяемый
скрипт добавляет только `group_member_catalog`; он не меняет данные и не расширяет
доступ к таблице профилей. Без него остальные разделы админа работают, а список
участников показывает сообщение о необходимом обновлении. Панель тем дисциплины
по-прежнему требует ранее подготовленное обновление v0.20.

Проверки: `npm test`, `npm run build`; браузер —
`VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npm run dev -- --port 5203`,
затем `npm run test:leader:browser`. Адрес можно изменить через `LEADER_TEST_URL`.
Для обновления опубликованного сайта нужна новая сборка и публикация.

### v0.24 · кабинет владельца

Владелец начинает с обзора проекта: группы, аккаунты, неархивные дисциплины,
ограничения доступа и уникальные участники по ролям. Старосты входят в число
студентов; несколько членств одного преподавателя не увеличивают число аккаунтов.
Обзор показывает группы без действующего старосты или дисциплин и ведёт в «Админ».
Эти показатели описывают загруженные данные, а не активность пользователей онлайн.

В «Админе» находятся группы, поиск участников с фильтрами роли/группы/доступа,
перенос студентов, дисциплины и назначения преподавателей, приглашения,
ограничения разделов, расписание, объявления, публикации в библиотеке и история.
Полная блокировка и восстановление доступа требуют подтверждения с именем цели.
Приглашение старосты по существующему контракту даёт право создать одну новую группу;
это не назначение старосты в уже существующую группу. Чтение и личные заметки
вынесены за пределы управления и используют тот же аккаунт.

История читается из уже существующей таблицы `audit_events`: только владелец,
с пагинацией, без редактирования или удаления. Демонстрация сохраняет историю
операций управления в своём браузере; содержимое личных заметок, ответов и
пригласительные токены туда не записываются. Табличные каталоги Supabase загружаются
полностью по страницам в стабильном порядке, чтобы стандартный лимит ответа
не скрывал аккаунты и не занижал показатели обзора.

Новое SQL-обновление для кабинета владельца **не требуется**. Проверки:
`npm test`, `npm run build`; браузер — запустите демонстрационный сервер на 5204
с пустыми `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` и выполните
`npm run test:owner:browser` (`OWNER_TEST_URL` меняет адрес).
Для обновления сайта нужна новая сборка и публикация.

## Профиль v0.25

Профиль открывается из меню или по имени аккаунта. Имя редактируется через существующие права `profiles`; фото и необязательные университет, факультет, специальность и курс сохраняются в метаданных собственного аккаунта Supabase. Фото обрабатывается на устройстве до JPEG 192×192, внешние URL и SVG не принимаются. Метаданные не определяют роли: группы и полномочия отображаются из действующих членств. Демонстрационные профили изолированы по аккаунтам в браузере.

Смена пароля требует текущего пароля и совпадения нового пароля с подтверждением. Настоящая проверка пароля выполняется Supabase; демонстрация её не имитирует. Смена почты и общая тема/уведомления пока не реализованы. Вкладка настроек объясняет существующие настройки читалки и открывает управление сохранёнными материалами. Нового SQL не требуется. Проверки: `npm test`, `PROFILE_TEST_URL=http://127.0.0.1:5205/ npm run test:profile:browser` при запущенном сервере разработки.

## Вход и регистрация v0.26

Основной экран всегда показывает настоящую форму входа: Email, пароль, «Войти», восстановление пароля и создание аккаунта. Демонстрация включается отдельно кнопкой «Посмотреть демоверсию» или явным `?demo=1` и не выдаёт настоящих полномочий.

Регистрация сохраняет имя и учебные сведения в аккаунте, проверяет повтор пароля и поддерживает включённое подтверждение email. При отсутствии сессии показывает инструкцию проверить почту; после подтверждения профиль и отложенная заявка создаются при первом входе. По приглашению группу повторно выбирать не нужно. Site URL и Redirect URLs в Supabase Auth должны соответствовать опубликованному адресу приложения. Восстановление пароля открывает отдельную форму нового пароля после события `PASSWORD_RECOVERY`; письмо отправляет Supabase. Проверки интерфейса используют имитацию Auth, реальная доставка писем не проверена.

**Перед публикацией примените [StudyHub_update_v0.26.sql](supabase/StudyHub_update_v0.26.sql) в Supabase SQL Editor.** Обновление повторяемое, сохраняет существующие членства. Выбор группы теперь создаёт заявку, не членство; старый RPC `join_group` также больше не выдаёт доступ автоматически. Староста обрабатывает заявки только своей группы в «Админ → Участники», владелец — в «Админ → Группы». Одобрение выдаёт только роль студента. Новый аккаунт до одобрения может пользоваться личными заметками и общей библиотекой; отключённые членства и запреты библиотеки остаются ограниченными. Ожидающая заявка показывает выбранную группу, скрывает повторный выбор и может быть отменена самим заявителем. Новая функция заявки должна существовать в базе: клиент не использует прежнее автоматическое вступление как запасной путь.

Проверки: `npm test`; `AUTH_TEST_URL=http://127.0.0.1:5206/ npm run test:auth:browser` при запущенном сервере разработки. Старые демонстрационные browser-проверки запускайте с `?demo=1`; проверка входа использует обычный URL. Перед публикацией выполните новую сборку с публичными переменными Supabase.

## Красный колокольчик v0.27

У «Объявлений» отображается красный колокольчик с числом непрочитанных сообщений доступных групп; у «Все задания» — с числом просроченных учебных работ самого студента. Староста учитывается как студент, преподавателю не показывается счётчик чужих просрочек. На телефоне рядом с заголовком страницы есть компактные переходы в разделы с событиями. Видимое число ограничено `99+`, доступная подпись сообщает полный счётчик.

Открытие списка объявлений не помечает всю страницу прочитанной. Нажмите «Отметить прочитанным» в конкретной карточке; отметка сохраняется в аккаунте Supabase и восстанавливается на других устройствах. Изменение уже прочитанного объявления не создаёт новое уведомление. Собственные публикации не считаются новыми для автора. Сданные и оценённые работы исключены из просрочек, возвращённая на доработку работа с истёкшим сроком учитывается снова. Открытие раздела не снимает просрочку: требуется сдача работы. Личные задачи планировщика в этот счётчик не входят.

Счётчики считаются сервером по действующим правам, без ограничения размером страницы каталога. Обновляются при переходах, собственных действиях, возвращении в приложение и раз в 60 секунд в видимой вкладке. Это уведомления внутри приложения, без push, звука или всплывающих окон. При отсутствии сети/ошибке загрузки старые счётчики скрываются; ошибка отмечена рядом с заголовком. Демонстрация хранит отметки отдельно для каждого аккаунта только в этом браузере.

Перед публикацией выполните [StudyHub_update_v0.27.sql](supabase/StudyHub_update_v0.27.sql): он включает обновление регистрации v0.26 и уведомления v0.27, допускает повторный запуск и сохраняет существующие членства и отметки прочтения. Проверки: `npm test`, `NOTIFICATIONS_TEST_URL=http://127.0.0.1:5208/?demo=1 npm run test:notifications:browser` при запущенном сервере разработки. Browser-сценарий проверяет 61 объявление, сохранение прочтения после перезагрузки, разделение аккаунтов, сдачу/возврат работы через интерфейс и экран 320 пикселей. Уведомления в настоящем Supabase требуют применения SQL; их живое подключение ещё не проверено.

## Обновление расписания — v0.33

Главная, календарь и студенческое расписание проверяют изменения раз в минуту в видимой вкладке, при возвращении в неё и восстановлении сети. Изменения занятия в этой вкладке сразу сообщаются открытым читателям. Обновление расписания не перезагружает задания и библиотеку на главной. Без сети показывается время сохранённой копии и предупреждение о непроверенных изменениях. Подробнее: [проверки и ограничения](docs/schedule-sync.md). Нового SQL не требуется.

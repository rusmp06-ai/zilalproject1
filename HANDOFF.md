## Главный ориентир продукта

Пользователь уточнил цель 11 октября 2026 года: дать студенту максимально удобные условия для учёбы. Материалы, дисциплины, лекции, расписание, библиотека, заметки и календарь должны быть под рукой. Продолжать существующий код этого архива. Пользователь намеренно отказался от старого проекта. Другой архив studyhub_pwa_stage13_fast_assistant.zip относится к прежнему StudyHub: не заменять им этот проект и не переносить его правила доступа автоматически.

Пользователь предпочитает практическую разработку небольшими завершёнными этапами и краткие пояснения на русском. Обычные обратимые доработки можно выполнять автономно. Если для подключения внешнего сервиса нужны отсутствующие параметры или доступ, сообщить конкретно, чего не хватает. Не выдавать демонстрацию за работающую платформу с реальными аккаунтами.

## 2. Согласованные продуктовые решения

### Регистрация и приглашения

- Студент регистрируется по общей ссылке с выбором группы либо по ссылке старосты с фиксированной группой.
- Доступ сразу: без подтверждения email и одобрения владельца. В настройках настоящего Supabase нужно отключить email confirmation.
- Владелец создаёт приглашение старосты. После принятия староста получает право создать собственную группу.
- Староста работает только в своей группе: создаёт дисциплины, приглашает студентов и преподавателей, управляет учебными материалами, расписанием и объявлениями.
- Староста приглашает преподавателя с назначением дисциплин своей группы. Повышенная роль выдаётся сервером после принятия приглашения; пользователь не выбирает её при регистрации.
- Один аккаунт преподавателя может работать в группах А и Б независимо. Новое приглашение добавляет назначение к существующему аккаунту.
- Студент сам не меняет уже выбранную группу: перенос выполняет владелец через интерфейс v0.10.

В коде приглашение действует 72 часа; преподаватель/староста — одноразовая ссылка, студент — до 60 использований. Одно приглашение старосты даёт создание одной группы. Это текущие параметры реализации, а не окончательное решение обо всех будущих лимитах.

### Роли и контент

| Возможность | Владелец | Староста | Преподаватель | Студент |
|---|---|---|---|---|
| Группы, пользователи, ограничения | Все | Только полномочия своей группы | Нет | Нет |
| Дисциплины и приглашения | Все | Своя группа | Принимает назначение | Принимает приглашение |
| Лекции, презентации, материалы | Все | Своя группа | Назначенные дисциплины | Чтение доступного |
| Задания и оценки | Все | Только при отдельном назначении преподавателем | Назначенные дисциплины | Свои сдачи и опубликованные оценки |
| Расписание | Все | Создание и управление своей группы | Чтение доступного | Чтение доступного |
| Объявления | Все | Все своей группы | Создание по назначенным дисциплинам, изменение/удаление своих | Чтение доступного |
| Общая библиотека | Все публикации | Добавление, изменение и удаление только своих | Чтение | Чтение |
| Личные заметки | Только собственные | Только собственные | Только собственные | Только собственные |

Староста без назначения преподавателем не создаёт задания и не выставляет оценки. Материалы дисциплины не попадают автоматически в общую библиотеку.

### Блокировки и приватность

Владелец блокирует/разблокирует аккаунт, группу, отдельный учебный раздел или дисциплину. Блокировка не удаляет данные. Проверки действуют на сервере для новых запросов, в том числе из уже существующей сессии. Владелец сохраняет административный доступ. Владелец не может заблокировать себя через текущий интерфейс.

Разделы ограничений: library, lectures, presentations, materials, assignments, course, schedule, announcements. Интерфейс создаёт запреты разделов для пользователя/группы; отдельный запрет дисциплины поддержан сервером, но его полноценной формы ещё нет. Индивидуальное разрешение поверх группового запрета не реализовано и не согласовано.

Работы и оценки других студентов скрыты. Черновик оценки и его комментарий студенту не выдаются. Личные заметки, а в будущем ИИ-чаты, не должны читаться в административном интерфейсе. Это контроль доступа, без сквозного шифрования: инфраструктурный администратор базы технически имеет привилегированный доступ.

Уже скачанные файлы невозможно отозвать. В приложении файлы скачиваются через авторизованный Storage API приватных bucket, публичные URL не используются.

4. 202610100004_course_materials.sql — материалы дисциплин.
5. 202610100005_assignments.sql — задания, сдачи и оценки.

10. 202610110010_course_reader.sql — личная позиция и закладки документов курса.

Новые изменения схемы добавлять следующими миграциями. Не применять эти миграции поверх базы старого StudyHub без отдельного плана переноса.

Клиентское чтение ограничено RLS; значимые изменения проходят проверенные RPC с security definer и фиксированным search_path. Прямые записи закрыты, кроме ограниченного создания собственного профиля. Повышенная роль не назначается из пользовательских метаданных регистрации.

Bucket: studyhub-library, studyhub-courses, studyhub-submissions — все приватные. Лимит файла 10 МиБ, общий бюджет 800 МиБ. Незавершённые загрузки резервируют лимит. Загрузка и удаление разделены на этапы, включая проверку Storage metadata. При сбое нельзя забывать резерв или допускать чтение неподтверждённого файла. Видео в пилоте не хранить.

Личные заметки: максимум 1000 записей и 1 МиБ суммарного UTF-8 текста/названий на аккаунт, запись до 50 000 символов. Версия проверяется при изменении и удалении. Учебная блокировка группы не закрывает личные заметки; блокировка аккаунта закрывает.

Текущие лимиты — настройки проекта. Перед реальным запуском отдельно проверить актуальные бесплатные квоты Supabase.

## 6. Проверки и честные ограничения

Последний успешный прогон: npm test — 5 тестов чистой модели прав, все 10 миграций и 9 SQL-контрактов в PGlite, 30 тестов интерфейса/адаптеров/валидации в jsdom. npm run build и npm run build:preview прошли; встроенный JavaScript preview.html проверен node --check, архив проверен на целостность.

PGlite использует имитацию auth.users/auth.uid и таблиц storage. Проверено выполнение PostgreSQL-политик и RPC, но это не полная интеграция Supabase. jsdom проверяет взаимодействия, а не внешний вид CSS.

Параметры тестового Supabase подключены в облачной среде; read-only Auth settings и каталог групп отвечают HTTP 200. Реальные email/Auth, загрузка байтов в Storage, полный визуальный аудит и публичный пилот ещё НЕ выполнены. PDF-читалка отдельно проверена в Chromium на мобильной ширине. Vite сообщает о размере JS-бандла около 2.8 МБ с PDF.js и встроенным worker; приложение пока собирается одним бандлом для автономного preview.

При переносе в облачную среду найдено зависание теста удаления записи расписания: сообщение об успехе появлялось до завершения асинхронного обновления списка. Немедленная проверка DOM-узла через assert.equal(element, null) при сбое приводила к огромному выводу внутренних связей React и исчерпанию памяти. Тесты удаления расписания и библиотечного материала теперь ждут исчезновения записи через waitFor; проверки отсутствия элементов сравнивают булево значение, чтобы ошибка оставалась короткой. Проверки прав и удаления сохранены, код приложения не менялся.

Для локальной работы:

```sh
npm ci
npm test
npm run build
npm run dev
```

Обновление демонстрационного файла:

```sh
npm run build:preview
```

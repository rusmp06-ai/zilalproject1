# StudyHub · актуальная передача · v0.47.0

Источник версии — `package.json`. Этот файл описывает текущее устройство, а не историю всех этапов. История прежних решений: [архив](docs/history/HANDOFF-v0.14.md).

## Цель и границы

Студенту должны быть доступны материалы, дисциплины, расписание, задания, чтение и личные записи. Пилот — 60 студентов четырёх групп, бюджет нулевой. До завершения пилота не расширять перечень возможностей. Gemini, OCR и оптимизация PDF — дополнительные инструменты; основной сценарий обязан работать без них.

## Решения

- Подтверждение email включено. При регистрации без приглашения группа выдаётся после одобрения заявки. Приглашение назначает серверные полномочия; роль нельзя получить из поля формы.
- Группа студента определяется его аккаунтом; повторного выбора нет. Староста тоже студент, управление вынесено в «Админ». Учебная группа и управляемая группа разделены.
- Стиль деловой, спокойный синий, мягкие углы, читаемые размеры и минимум вспомогательных советов.
- Личные заметки и работы доступны только разрешённым аккаунтам. Скрытие интерфейса не считается защитой.
- Недельное расписание вводится по дням, дисциплине и времени. Исключение меняет только выбранную дату. Старые записи на даты сохраняются.

## Источники и команды

- `supabase/migrations/` — единственный источник SQL. Не изменять ранее выпущенные миграции: исправления добавляются новой миграцией.
- `npm run sql:generate` создаёт скачиваемые SQL. `npm run sql:check` и тест схемы обнаруживают рассинхронизацию.
- `npm run format` / `npm run format:check` — Prettier. Изменения форматирования отделять от изменений поведения.
- `npm test` — все найденные Node/SQL/UI-тесты с итоговым отчётом. `npm run verify` — полный прогон. CI описан в `.github/workflows/quality.yml`.
- `npm run build` / `npm run build:budget` — production и проверка начального трафика. `preview.html` генерируется, в Git не хранится.
- Поддержка Node 22 начинается с **22.22.2**, Node 24 — с **24.15.0**. Deno edge-тестов — **2.7.1**.

## Карта

`App.tsx` содержит состояние входа и маршрутизацию. `AppHeader.tsx` и `AppSidebar.tsx` — оболочка. Разделы загружаются через React.lazy/Suspense с восстановлением после ошибки загрузки. `types.ts` — контракт Gateway; `api.ts` — реальная интеграция, `demo.ts` — симуляция. Демо не является проверкой безопасности.

Недельное расписание: `WeeklyScheduleEditor`, `SchedulePanel`, `weekly-schedule`, серверная миграция. Читалка: `ReaderPanel`, `CourseReader`; PDF/OCR/оптимизатор загружаются отдельно. Service Worker описан читаемым кодом в `scripts/service-worker.js`, список основных файлов формируется при сборке. `scripts/check-course-sync.mjs` — отдельная реальная проверка Auth/Storage с удалением временного документа и локальным выходом тестовых сессий.

## Проверки и внешняя среда

Актуальные результаты и ограничения — в [pilot-readiness](docs/pilot-readiness.md). Не переносить старые отметки «не проверено» или «прошло» на текущую версию без указания даты и сценария. Не выдавать PGlite, демо или мобильную ширину Chromium за испытание живой системы на физических устройствах.

Существующие имена переменных и авторизация сохраняются между задачами. Проверять наличие по именам, не печатать значения. Не просить пароль или service_role в чате. Ручное выполнение SQL не заполняет историю Supabase CLI: перед переходом на CLI сверить схему и историю, не применять migration repair вслепую. Правила развёртывания — [deployment-current](docs/deployment-current.md).
